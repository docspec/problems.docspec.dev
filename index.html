DocSpec problem types

The DocSpec HTTP API reports failures as RFC 9457 problem details. The type member identifies the class of failure; switch on it rather than on detail, which is free text. Types are chosen by the kind of the underlying error, never by its message. Where the status code already says everything, the type is about:blank.

malformed-input

Type
https://problems.docspec.dev/malformed-input
Status
422 Unprocessable Content
When
The parser or emitter rejected the document's structure: a syntax error, or a document that ends before its structure closes. Raised for core Parse and Json errors.
What to do
The document is the problem. detail names where it broke; fix the file and retry.

unsupported-content

Type
https://problems.docspec.dev/unsupported-content
Status
422 Unprocessable Content
When
The document is well-formed but holds a dangling reference, a missing media part, or a value the output format cannot represent. Raised for core Other and Io errors, and for any error kind added later.
What to do
The document is the problem. detail names the reference, part or value; repair or remove it and retry.

resource-limit

Type
https://problems.docspec.dev/resource-limit
Status
422 Unprocessable Content
When
The document is within its format but beyond a bound of this build: a DOCX package part or XML node over 64 MiB, or tables nested deeper than 100. Raised for the core Limit error kind.
What to do
The document is the problem. detail names the cap; a document this large or deep is almost always a crafted one.

conversion-timeout

Type
https://problems.docspec.dev/conversion-timeout
Status
503 Service Unavailable, with Retry-After
When
The conversion ran past the server's configured time limit and was stopped at its next event. The document may be fine; the server declined to spend more time on it.
What to do
Retry after the seconds in Retry-After, or ask the operator to raise --conversion-timeout. Repeated timeouts on one document mean it is too expensive for this server.

about:blank

Type
about:blank
Status
400, 404, 405, 406, 413, 415, 500
When
The status code is the whole meaning. The title is the HTTP reason phrase.

Every problem body also carries instance: the request id as urn:uuid:<X-Request-ID>, present whenever the request id is a UUID. Quote it when reporting a failure.
